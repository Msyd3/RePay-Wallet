# RePay Wallet

واجهة عربية/إنجليزية للمحفظة، ملخص العملية، نتيجة الدفع، الملف الشخصي، الدخول ورمز التحقق. Rubik للعربية وNunito للإنجليزية والأرقام.

هذه نسخة الواجهة جاهزة لربط خدمات الإنتاج؛ **لا تتضمن خادم محفظة أو إرسال SMS أو بوابة دفع**. إعداد الإنتاج لا يعرض بيانات تجريبية ولا يقبل رمز تحقق وهميًا. التحويل والسحب يبقيان بدون إجراء وفق التصميم المعتمد.

## الهيكل

- `public/`: الصفحات وCSS والأصول وJavaScript.
- `public/js/core.js`: الأرقام والمبالغ والتحقق وطلبات API مع CSRF.
- `public/js/config.js`: إعداد الإنتاج ونقاط ربط الخدمات.
- `public/js/pages/`: سلوك مستقل لكل صفحة.
- `tests/`: اختبارات منطق الأمان وبيانات معاينة منفصلة.
- `scripts/`: فحص المشروع وبناء النسخة.
- `docs/api.md`: العقد المطلوب من الخادم.

## التشغيل والفحص

Node.js 24، دون حزم خارجية:

```sh
npm run check
npm test
npm run build
python3 -m http.server 8080 --directory dist
```

للمعاينة فقط:

```sh
npm run build:demo
python3 -m http.server 8080 --directory dist-demo
```

ابدأ من `/login.html` أو `/home.html`. `/index.html?id=opaque-id` هي صفحة ملخص العملية لروابط واتساب. لا تضع بيانات العملاء أو المبلغ أو رمز OTP في الرابط.

## الإنتاج

انشر `dist/` فقط خلف HTTPS وخادم يدعم العقد في docs/api.md. المصادقة تكون عبر cookies من نوع HttpOnly/Secure/SameSite، ولا تخزن رموز الدخول في JavaScript أو localStorage. يُحفظ تحدي OTP مؤقتًا في sessionStorage؛ لا يُحفظ الرقم أو رمز OTP فيه.

ملف `_headers` للاستخدام مع استضافة تدعمه؛ على الاستضافات الأخرى طبّق القيم في الخادم. GitHub Pages لا يطبّق هذا الملف ولا يشغّل API، ولذلك يصلح للمعاينة وحدها. يجب تكييف CSP لمزوّد الدفع المختار فقط عند ربطه.

أضف SDK مزوّد الدفع ومعالج `onPay` بعد تهيئة Apple Pay على النطاق. يحدد الخادم المبلغ والمستفيد ويرجع الحالة الموثّقة. لا تُفعّل الدفع بإرجاع نجاح ثابت من الواجهة. صفحة النجاح تتحقق من API مرة أخرى.

الخادم مسؤول عن صلاحيات كل حساب وعملية، وحدود OTP، والتحقق من CSRF وOrigin، وidempotency للعمليات المالية، والتأكد من webhook الخاص بالمزوّد، وسياسة الإخفاء والتدقيق. اختبارات الواجهة لا تثبت أمان خادم غير موصول.
